# 真实文本上的AR到扩散模型适配

状态：2026-11-01训练前设计，未实施新训练。用户同意先检验适配有效，再检验具体优势；保留180 CU总上限和三个共同学习节点。下述为当前方案，尚未完成可运行实现与全部评价细节锁定。

## 两个问题分开回答

1. **适配有效吗？** 已有Qwen2.5-0.5B权重能否学习掩码去噪，并在没有正确答案可见时生成可读的真实文本续文？
2. **有什么收益？** 在合理AR基线面前，是否能在质量接近时减少生成开销，或在获得相同前后文的补全任务上更有效？

第二个问题可以得到否定或不确定结论；第一个问题也不能只靠loss下降通过。不存在通用的“loss低于某值就算转换成功”标准。

针对“训练不足还是采样导致不连贯”，新增[检查点与采样器交叉诊断](training-sampling-diagnosis.md)。它是待执行的设计，包含相同权重下更换采样器、相同采样器下比较训练进度，以及高遮盖和真值上下文诊断；不将二者强行视为互斥原因。

## 主对照

| 组别 | 作用 | 新训练 |
| --- | --- | --- |
| 原始AR | 记录原有语言能力与生成行为 | 无 |
| 继续训练的AR | 控制新增语料和训练投入带来的收益 | 与DLM相同的基础权重、语料和样本曝光量 |
| 适配后的DLM | 检查改变注意力、去噪目标与生成过程的效果 | 真实预训练权重起步，全参数训练 |

另保留未训练的双向去噪版本作DLM前后诊断；其崩溃不能替代原始AR基线。三组不复用上轮200步LoRA检查点。目标基座沿用已校验的Qwen2.5-0.5B固定版本；本轮不扩大到7B。

AR和DLM各保留三个种子的设计目标。先测实际成本，再锁定共同训练量；报告相同样本曝光和实际训练成本两个口径，不声称二者天然相同。

## 先建立原始Qwen的标准评测基线

2026-11-02用户指出，不能继续只围绕坏样例试超参，必须与原始Qwen2.5-0.5B比较。下一步优先建立基线及冻结评测协议；采样改法仍是候选诊断，不能代替主评价。

小模型并非不能跑标准benchmark。Qwen官方Base评测中，Qwen2.5-0.5B在GPQA为24.8%，HellaSwag为52.1%，ARC-C为35.6%。这些是官方对应协议的结果，不是本项目实测，不能把不同few-shot或评分设置下的本地结果直接与它们相减。GPQA成绩接近四选一随机水平，因此不建议作为本轮主要区分指标。[Qwen官方Base评测](https://qwenlm.github.io/blog/qwen2.5-llm/)

建议的任务组合（尚未执行）：

- **HellaSwag为主要候选**：选出合理的事件续文，检验适配后是否保留原有语言与常识判断能力。
- **PIQA、ARC-Easy作补充候选**：分别检查日常物理常识与基础科学问答。先核原始基座在固定开发样本上的有效信号，不声称其本地分数已经测得。
- **真实文本续写另成一张表**：看生成质量、重复、终止与耗时。选择题表现不证明自由生成连贯，也不能用重复率替代选择题能力。

任务来源：[HellaSwag](https://arxiv.org/abs/1905.07830)、[PIQA](https://arxiv.org/abs/1911.11641)、[ARC](https://arxiv.org/abs/1803.05457)。候选选择依据是对原始模型有区分度及与研究问题相关，不能因DLM在哪项得分高就事后更换主任务。

评测协议要求：

1. 先选定开发集、最终评测集、版本、题目ID、few-shot示例和长度归一化；开发与最终集合隔离，不按测试结果挑提示词、温度或检查点。
2. 原始AR、继续训练AR、适配DLM采用相同题目、上下文与正确答案口径；记录Base/Instruct身份，当前基座为Base。
3. 对选择题采用候选答案评分。AR可计算条件对数似然；DLM使用与其目标相符的条件似然界/估计，并记录噪声采样次数、随机误差和排名稳定性。不能把一次全遮盖的逐词CE直接当成精确联合似然，也不能比较两类模型原始loss数值大小。
4. LLaDA官方提供了HellaSwag、PIQA等任务的条件似然估计范例，但须适配本项目的shift、掩码输入和归一化，不能直接套用LLaDA的位置对齐。[官方评估说明](https://github.com/ML-GSAI/LLaDA/blob/main/EVAL.md)、[估计实现](https://github.com/ML-GSAI/LLaDA/blob/main/get_log_likelihood.py)。
5. 模型候选评分和生成采样分开。若评分直接基于去噪预测器，它不经过重掩码/贪心生成循环；这样可以区分模型判断能力变化与解码策略变化。
6. 小样本先用于接口核对和成本测量，不把几个题的涨跌当有效改进。最终报告配对结果、样本量、区间及独立训练种子的变化，不只报告最高分。

目前标准benchmark尚未运行，原始Qwen基线缺口仍未补齐。本节是收敛评价优先级与候选方案，不是新的实验结果或训练启动许可。

## 语料与划分

- 现有WikiText-2仅用于调试与回归检查。此前测试结果已经被查看，后续使用它必须标记为已观察的诊断集，不能重新冒充未触碰的最终测试。
- 当前候选主语料为同一公开数据仓库中的WikiText-103 raw；沿用已发现的数据版本作为待核固定版本。它是英文百科文本，不能据此宣称中文、聊天或通用指令能力。
- 正式训练前按文章识别边界，固定清洗、去重、划分和token化流程；排查与旧预实验已用文本的重合，另锁定尚未用于调参的评估题与提示词。
- 基座可能预训练过这些文本；“留出”仅指本轮适配。报告这一限制，不声称无预训练污染。
- 不靠无限重复原来1024个段落消耗预算。数据版本、实际训练量与重复遍历次数必须进入结果清单。

来源：[WikiText数据卡](https://huggingface.co/datasets/Salesforce/wikitext)。

## 三层评估

**去噪诊断。** 在固定留出文本上使用25%、50%、75%的固定随机掩码，比较DLM适配前后masked CE与恢复准确率。AR的下一词CE单列，两种条件分布的loss不得混排优劣。

**实际生成。** 从固定真实文本开头出发，答案区域不提供真实续文；统一生成长度上限、终止规则及提示词集。记录重复、空输出、异常终止、可读性、上下文连贯性和条件遵循。开放续写不以原文逐字匹配为唯一正确答案。分开机械退化指标与匿名人工评价；模型评审若使用，仅作辅助，不能冒充人工或独立客观评分。

**质量与成本。** 比较多个DLM去噪步数下的质量和实际耗时，并使用合理AR生成配置。测速对齐设备、批量、输出长度和测量范围，AR启用正常KV cache；不能仅比较轮数。若尚无法证明质量相近，不下“更快且更好”的结论。

前后文补全暂为第二阶段候选。若开展AR对照，AR必须得到相同的前后文，并具备适当的填空训练/格式；不能把只看到前文的AR作为“公平”基线。当前不因DLM能自然接收右侧上下文就提前宣布补全优势。

## 预算和进入训练的条件

总上限180 CU，不要求用满；包括加载、训练、评估、重试和空闲。先完成最多2 CU的短时全参数训练资源测量，且必须在训练前学习节点之后。资源费率重新读取，旧7B LoRA吞吐不用于直接报价。

Countdown方案的阶段分配、64-token算式输出及5个百分点成功率阈值不直接迁移到真实文本任务。短测前须明确：数据清单、掩码与EOS/padding实现、采样策略、评估提示词、退化指标定义、人工评价规程、阶段预算与保存/停机方式。长训练前锁定重复次数和训练量，不按测试结果不断换标准。

三个节点：训练前用具体文本理解输入/目标/损失；短测后共同解释显存、吞吐与生成诊断；完整运行后共同解释结果并完成笔记。节点讨论前释放付费GPU。共同讨论不是独立掌握的证明。

## 当前已有证据

上轮0.5B预实验显示masked CE下降而生成明显重复，支持本轮必须同时检查去噪和自由生成。它不证明真实文本适配已成功，也不能作为本轮的最终实验结果。

代码核对还确认：旧采样器固定输出32个token，并禁用了全部特殊token（包括EOS）。它是固定长度诊断样例，未验证正常终止能力。新实验必须独立检查EOS与padding处理；这一发现本身不能确定重复生成的原因。

后续已完成[旧200步权重的1/8-token采样分组对照](sampling-group-size-results.md)。两份检查点各12个提示词，权重未更新；较小步幅减少了部分重复，但两组仍退化，完整训练进度×采样矩阵及EOS正常终止评估尚未进行。此次结果不能作为追加长训练必然成功的依据。
