## 2. 第一轮具体跑什么

### 数据与对照

首轮是开发小测，使用已下载、已观察过的WikiText-2：512个训练段落、32个验证段落；不会把它称为未触碰的最终测试。准备脚本固定行号、文章标题、文件摘要，核对本次训练和验证文章不重合。

每条为128-token前文＋最多128-token续文（另加一个BOS约定符号）。不足136个token的段落不入选；真实段落末尾加入EOS，截断到256的位置不伪造EOS；padding既不作为可见key，也不作为训练目标。这里EOS表示段落结束，是本项目的数据处理约定。

| 条件 | 权重来源 | 更新次数 | 用途 |
| --- | --- | ---: | --- |
| 原始AR | 固定版本Qwen2.5-0.5B Base | 0 | 原有能力参照；单独生成32条续文 |
| 继续训练AR | 同一原始基座，全参数 | 20→200 | 控制相同语料曝光的继续训练 |
| 适配DLM | 同一原始基座，全参数＋可学习mask向量 | 20→200 | 双向注意力、shift预测、掩码去噪 |

不加载旧LoRA。第一轮只用训练种子11；32个前文和单训练种子只能用于开发诊断，不能证明稳定优势。20步包含在200步内，不额外再训200步。

### 固定训练设置

| 项目 | 首轮设置 |
| --- | --- |
| 更新范围 | 全部基座参数；DLM另训练mask向量 |
| 数值设置 | FP32参数/梯度/Adam状态，BF16 autocast，梯度检查点；不把纯BF16 Adam误称为FP32主权重训练 |
| 有效batch | 16条，micro-batch 2、累积8次；OOM时先停机，另记录micro-batch 1、累积16的重跑，不能偷偷改变有效batch |
| 优化器 | AdamW，学习率2e-5，betas=(0.9,0.95)，weight decay=0.01，clip norm=1 |
| 学习率计划 | 前20次更新线性warmup，随后常数；首轮不比较其他学习率 |
| AR目标 | 相同前文条件下的续文next-token CE，按每条有效续文长度归一化 |
| DLM目标 | 前文保持可见，仅续文按每例t~Uniform[0.1,1)独立掩码；shift位置预测；masked CE除以有效续文长度与t，再按batch平均 |
| DLM生成 | 贪心、置信度最高的位置优先；128槽位，分别16轮（每轮8token）和128轮（每轮1token） |
| AR生成 | 贪心、正常KV cache，最多128新token；EOS早停 |
| EOS解释 | 两方允许EOS、禁止其他特殊token和词表空槽；DLM完成整张画布后按第一个EOS截断，同时报告全部计算量 |

DLM本轮使用截断噪声区间的条件去噪目标，**不是完整ELBO，也不是Dream原论文配方**。不启用CART或新重掩码策略；只有在实现稳定后才能把额外方法列为单独消融。

相同样本顺序、有效batch和200次更新给出相同文本曝光量；DLM真正受监督的掩码token数通常更少，计算量也不同，分别记录。总输入曝光最多819,200 token/方法（不含BOS），实际量因短段落而减少；不能写成训练了819,200个互不相同token。

### 小测的输出与判读

- 分别报告AR条件NLL与DLM在25%、50%、75%、90%、100%遮盖下的CE/恢复率；不横比两种loss大小，不将masked CE指数化包装成同口径PPL。
- 固定32个前文：原始AR32条、继续训练AR32条、DLM两种采样各32条，共128条主开发续文。P0少量样本和中间检查点输出另存，不冒充这128条已经齐备。
- 报告空输出、EOS位置、实际长度、重复、生成时间及前向次数。首次运行的时延含预热影响，首轮仅用于资源估算；正式测速另做预热与重复。
- Flash比较：每种DLM采样分别对继续训练AR、原始AR。`32×2采样×2对照×2顺序=256`次基础调用；另预选13个逻辑比较对复评双顺序，共26次稳定性调用。
- 校准沿用60对/120调用；人工标签必须确实经过人工确认，不能把AI自判当金标准。用户尚未核验的材料标记待核，不抢跑正式评分。
- 训练损失下降但高遮盖诊断与续写不改善：先查目标、EOS、训练数据和采样，不能直接扩大训练。1-token采样优于8-token，只说明当前检查点对采样敏感，不能认定训练充分。
- 通过首轮的含义是“链路、资源和诊断有效”。若两种采样仍严重退化，保留所有失败输出，先在开发集定位原因；不以单次小样本胜率宣布DLM更快或更好。

## 3. 预算：6 CU首轮，180 CU总上限不变

| 预算桶 | 原上限 | 本轮使用 |
| --- | ---: | --- |
| A：正确性/吞吐/续训短测 | 2 CU | P0最多2 CU |
| A：小规模训练/学习率筛选 | 12 CU | P1最多4 CU；余下8 CU留筛选 |
| A：正式训练 | 100 CU | 首轮不使用 |
| A：正式自身评测 | 16 CU | 首轮不占用；其中4 CU仍用于最终裁判样本生成 |
| A：恢复/收尾 | 10 CU | 首轮不提前动用 |
| B：成熟模型评测 | 40 CU | 首轮不使用 |
| 合计 | 180 CU | 首轮最多6 CU，包括加载、保存、生成及GPU空闲 |

6 CU是停止上限，不是预计会用满。连接时读取当前设备、费率和余额；历史A100费率5.3 CU/h仅对应约68分钟的6 CU时间量，不能当当前报价。P0若未通过，不自动消耗P1的4 CU。

按稳定训练步（排除前5步）的耗时，另加实测加载/评估/保存时间及20%余量预测P1；只有在剩余4 CU内可完成才续到200。正式训练同理：用各方法实测速度，先定六次训练能共同完成的样本曝光量，不用旧7B LoRA吞吐报价。

代码的`--max-seconds`是最佳努力的本进程时间保护，不是Colab计费硬开关；单次前向、保存、平台连接时间仍需外部监控。运行前先减去本阶段已花CU，再留至少0.5 CU用于保存/释放；余额达到阶段停止线时停止新增工作、保存并释放GPU。失败/超时/重试计入原预算，不能开新会话重置台账。

## 4. 从小测到正式实验需要锁定的事项

1. **正式语料**：WikiText-103 raw固定版本，按文章建立清单，排除与旧WikiText-2已用文章的重合；从剩余文章预先按哈希划出300个最终续写文章及100个开发文章，再划校准来源。它是本项目自定义留出集，不能称为官方test split。文章不足/边界不可靠时停下核对，不把同一文章的300段说成300篇独立文章。基座预训练污染未知。
2. **共同训练量**：按P0/P1实测，在100 CU正式训练桶内给AR/DLM的11、22、33三个种子锁定相同样本曝光；长跑每25%保存权重快照，最近可恢复状态另含optimizer/RNG。单个种子不因坏结果被排除。
3. **学习率筛选**：剩余8 CU内，候选1e-5、2e-5、5e-5；两种方法同样开发预算，允许各自选合适学习率。先依据数值稳定与各自留出目标筛选，开发续写用于检验明显退化；不拿DLM/AR不同loss互相比大小，不反复调用裁判花完预算。资源不够则在看结果前缩减候选并记录。
4. **最终生成设置**：在开发集选择一个主设置。300前文、7组输出和Flash3,600正式调用按已有裁判方案；完整多采样器消融先留在开发集，不把每个正式解码条件都追加付费评分。正式质量—耗时主比较用同一批输出。
5. **建模评价**：先保证AR条件NLL与DLM固定遮盖诊断可重跑；完整DLM似然界只有推导/实现另经核验后才加入，不将首轮截断目标改名为似然界。
6. **HellaSwag自身能力保留**：先32道独立开发题做评分接口校验；候选正式规模500题、DLM每候选128 MC，含MC误差与长度归一化说明，原始AR/继续训练AR同题。该评分适配器尚待实现并验证，只有实测可落入剩余12 CU自身评测预算才冻结规模。与成熟7B已定1,000题协议分开，不按分数高低删题。
7. **成熟模型**：完整沿用[7B协议](dream-qwen-hellaswag-plan.md)；小测不下载Clover，不借用自己训练预留额度。是否出现速度收益由结果决定。

## 5. 已有运行入口与执行命令

本轮入口：`experiments/prepare_pipeline_pilot.py`、`experiments/full_parameter_pilot.py`；正确性检查：`tests/test_full_parameter_pilot.py`。旧训练/采样脚本不修改。以下命令在项目目录执行；本地Windows用`python -s`，干净Colab环境用`python`即可。

本地准备（不连接Colab、不调用API）：

```sh
python -s -m pytest tests -q
python -s -m experiments.prepare_pipeline_pilot
```

Colab先准备匹配Python/PyTorch/Transformers版本的独立环境，再连接A100；`requirements.txt`锁定的小模型栈不能和7B Dream栈混装。若需下载基座和旧公开数据，先在CPU运行`experiments/prepare_data.py`，再运行上述数据准备；文件不提交到Git。至少预留25 GiB存储空间供两份FP32可恢复训练状态、临时原子保存及模型数据，实际以文件大小核对。

P0下列每条`450秒`只是示例，须用连接时费率、已用额度和保存余量重新计算，**不能靠示例时限担保2 CU**。两条必须顺序运行并在每条后检查余量，第二条不是无条件启动：

```sh
python -m experiments.full_parameter_pilot --method ar --steps 20 --eval-examples 8 --max-seconds 450 --output checkpoints/pipeline-ar-11
python -m experiments.full_parameter_pilot --method dlm --steps 20 --eval-examples 8 --max-seconds 450 --output checkpoints/pipeline-dlm-11
```

P0完成后先退出进程，再恢复；真实GPU恢复检查需比对相同步数、optimizer状态、样本/掩码状态和一步更新。CPU小模型的精确恢复测试不能替代GPU验证。P1按核准剩余时间运行；下面`600秒`同样是需替换的示例：

```sh
python -m experiments.full_parameter_pilot --method ar --evaluate-only --eval-examples 32 --max-seconds 600 --output checkpoints/pipeline-original-ar
python -m experiments.full_parameter_pilot --method ar --steps 200 --resume --eval-examples 32 --max-seconds 600 --output checkpoints/pipeline-ar-11
python -m experiments.full_parameter_pilot --method dlm --steps 200 --resume --eval-examples 32 --max-seconds 600 --output checkpoints/pipeline-dlm-11
```

`latest.pt`保存可恢复状态；`report-start-end.json`保存训练日志、前后诊断和所有实际生成。`partial`必须保持为未完成，不能混入完整样本均值。每个输出目录只属于一个固定配置；修改数据/代码/训练配置后拒绝直接续训。正式进入P1前应另保存P0报告与checkpoint摘要。

训练前学习节点的最小例子：前文“The bird landed on”固定可见；参考续文“the branch.”只用于训练。AR依次用正确历史词预测下一词；DLM先把续文部分替换为mask，再预测被遮住的原词。评测续写时两者都没有参考续文；DeepSeek只看到前文和生成文本、看不到模型名和训练loss。短测后用真实日志再讨论这一差别。
