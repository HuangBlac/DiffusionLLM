# 撤回与重掩码的实现核对

核对日期：2026-11-02。用户提出全局置信度重掩码、随机回退与末尾局部精修。本轮核对官方实现及方法条件，未实现或运行新采样器，未下载新模型权重。

## 三个概念分别记录

- 对当前掩码位置产生候选，再决定本轮揭示哪些位置：可以不改变任何此前已提交token。
- 真正撤回：把此前已提交的生成token重新置为掩码，后续再预测。
- 局部编辑：固定前后文，只生成指定缺口；能够指定缺口不等于模型会自动识别错误。

变量名或README中的remasking不能单独证明实现了第二种行为，应看采样循环的状态更新。

## 为什么全局直接复评分需要修正

双向注意力下，位置i的词已可见时，对该词的预测可以利用它本身。Dream式shift把读出位置移到i-1，却没有阻止i-1通过注意力看到i。当前去噪训练只监督被遮住的目标，因此可见位置的logits不保证是校准过的纠错置信度。

更有意义的候选诊断是先隐藏被检查的词，再询问模型对旧词的支持度：

\[
c_i=p_\theta(x_i^{\mathrm{old}}\mid \mathrm{context},\tilde{x}_{\setminus i},\tilde{x}_i=\mathrm{MASK}).
\]

这仍然只是模型条件支持度，不是“该词正确的概率”。必须区分旧词的概率与该位置最大候选概率：若旧词支持低、另一候选支持高，不能用后者把旧词判成可靠。

逐位置leave-one-out评分通常需要额外前向；可以批处理或分组遮盖近似，但分组改变了条件，成本也不能隐藏。新掩码位置与可见位置直接读出的概率不应未经校准混在一起排名。

若用户例子中原有26个明文、下一轮目标39个，撤回r个旧词后，需要新接受13+r个词才能达到39。外部固定提示词不参加重排。重掩码与直接用另一词覆盖是不同更新规则；先评估重掩码，不同时混入无条件覆盖。

## 已有撤回方法及理论边界

- [ReMDM](https://arxiv.org/abs/2503.00307)为预训练掩码扩散模型构造允许重掩码的反向过程。
- [CoRe](https://arxiv.org/abs/2602.04096)通过遮盖上下文扰动检查token支持度的变化，避免只依赖静态置信度。
- [RemeDi](https://arxiv.org/abs/2509.23653)联合预测token与置信度，并专门训练重掩码能力；不能将其效果当成普通去噪模型直接拥有的能力。

任意“随机遮回5个词”可以是再加噪—去噪启发式，但并不自动成为朗之万修正。离散predictor-corrector的分布性质需要由具体转移核和相应假设说明；不能仅因走了回头步就宣称保留目标分布或必然消除不协调。

## 局部精修的边界

支持双向补全的模型可以将指定片段遮住后重填，并由程序保持外部token不变。但两三轮就自然贴合上下文不是保证；错误定位、模型能力、缺口长度和解码预算都会影响结果。块扩散模型的跨块上下文与缓存限制还需分别检查，不能把全画布模型的用法直接推广到所有实现。

“GPT/AR绝对做不了”也不成立：AR模型可经FIM训练读取重排后的前后文，再生成中间部分；应用也可生成局部补丁并保留其余内容。[FIM研究](https://arxiv.org/abs/2207.14255)已有明确方法。扩散的直接掩码画布接口与AR的序列化补全不同，但局部编辑能力不是扩散独占。

## 下一轮候选对照（尚未实施）

保留现有固定权重与提示词，比较：不撤回、随机重掩码、遮盖后复评分再重掩码。将全局可见词直接复评分作为有偏启发式对照时须明确标注，不能作为可靠纠错基准。

控制总前向计算与实际时间；批量评估多个遮盖副本时记录样本数，不能将整批LOO评分当成一次普通前向。单独记录撤回次数、真正改词次数、改后重复/连贯性、固定上下文是否保持以及是否循环。设置总轮数、每位置撤回次数和最终清空掩码规则，防止无限回退。EOS、温度与重复惩罚另作独立变量。

当前证据只支持将撤回纳入待测方案，不支持其已能修好现有200步模型。
