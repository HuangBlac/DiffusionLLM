## C Clover是可选扩展，不自动加入第三项必做任务

用户提出Clover-35B-A3B-Preview作为更大成熟模型候选；尚未决定替换Dream或启动Clover评测。

官方资料核对：

- Clover总参数约35B、每token激活约3B。激活规模不能直接用于估算全部权重的存储需求；官方HF路径要求BF16权重约69GB，另加推理状态。
- 因而A10040GB不能按该路径全量驻留权重。历史测过的G4约95 GiB可用显存是候选设备，但实际可用性、上下文长度、运行时开销与峰值显存需要另测；不能保证任意配置都装得下。
- 匹配的主要AR候选是其所基于的Qwen3.6-35B-A3B，使用文本输入。同档位匹配仍不是只改变扩散/AR机制的因果对照，训练配方和架构变化要披露。
- Clover HF建议环境为Transformers 5.19.0、PyTorch 2.10或更高，不能直接复用Dream的4.46.2/2.5.1环境。需另核评分算法、位置对齐、thinking模式、EOS、默认惩罚与块解码配置，不能仅替换模型名称。
- SGLang与llama.cpp的自推测解码路径，不等同于HF的块扩散解码。框架及模式必须成对说明；不能把额外的推测加速全部归因于扩散。若使用量化或CPU卸载，也需另设匹配对照，不能拿一方量化/卸载与另一方BF16结果直接归因。

建议先完成A+B。Clover仅在A的140 CU保留额度不被动挤占、B有足够结余且另有明确方案时，再考虑小样本扩展；否则重新讨论总方案内的取舍，不自动增加总预算。不会因为“更大模型”就跳过自己的适配训练。
